| Priority | Domain | Issue | Why it matters | Recommended next action | Blocking |

| P1 | Boxer beta user testing | The app is now sectioned and more understandable, but no real boxer beta usability findings have been captured yet. | IA choices need validation under real training-day fatigue, weigh-in pressure, and quick-log interruptions. | Run guided beta sessions on Today, Fuel Command, Train Workout, Plan Week/Next Week, and Profile Data flows. | Blocking for confident beta polish, not for current local smoke. |
| P1 | Coach activation boundary | The Edge Function now requires a Bearer JWT, verifies the caller with Supabase Auth, and only lets the athlete activate a pending relationship, but production audit logging/admin policy and UI gating are still incomplete. | Coach-only commands must not ship broadly until active status, consent, permissions, and audit behavior are proven end to end. | Add audit events, deployed function tests, admin/team policy, and athlete-facing consent copy before exposing coach UI. | Blocking for shared coach accounts. |
| P1 | Permissioned nutrition review workflow | Nutrition safety reviews now persist rows/events, athlete acknowledgement, and athlete-facing history panels, but there is no coach/clinician/dietitian reviewer UI, no messaging, and no exposed reviewer-clear workflow. | Hard stops are visible, persisted, and cannot be self-cleared, but real review operations still need permissioned reviewer identity, relationship policy, and audit behavior. | Add reviewer permissions through coach/clinician relationship policy or a trusted server-side function before exposing `cleared_by_reviewer`. | Blocking for production review workflow, not for current safety copy. |
| P1 | Team memberships | `coach_team_memberships` was deferred. | A coach/team model will eventually need more than one-to-one athlete-coach rows. | Add team membership tables only after the one-to-one active relationship and permission model is proven. | Blocking for team workflows, not athlete-only use. |
| P2 | Numeric load progression | Free-text `loadText` is summarized but not parsed for progression. | Avoids fake progress and unsafe assumptions, but limits strength progression precision. | Add structured load fields later; keep free-text as notes until then. | Non-blocking. |
| P2 | Generated-session catalog depth | Accepted previews now materialize conservative future support sessions, but the mapping intentionally uses a small safe family set. | The durable future week is workout-ready, but advanced support variety should not be added without more catalog validation. | Expand family-specific templates only with prohibited-term tests, hard-day-cap tests, and no numeric load inference. | Non-blocking. |
| P2 | Mobile UX polish | Section tabs reduce density, but quick logs, workout completion, and Plan adjustment controls still need hands-on mobile polish. | Beta users will interact on phones between sessions; dense input flows can reduce logging consistency. | Observe beta users, then split the densest forms into sheets/steppers without moving logic into screens. | Non-blocking. |
| P2 | Routed drilldowns | Fuel, exercise, block, and audit histories are clearer panels, but there are no routed drilldown screens yet. | Panels are enough for beta comprehension, but longer histories need dedicated space and comparison views. | Add routed, view-model-driven Fuel history, exercise history, block history, and audit screens after user testing. | Non-blocking. |
| P2 | Plan adjustment UX | Plan controls are sectioned and athlete-only in UI; coach move controls are not exposed and drag/drop remains deferred. | The command model is safer, but repeated weekly planning still needs clearer interaction design. | Add clearer feedback, date picking, and safer move-session flow after coach permissions and preview persistence are hardened. | Non-blocking. |
| P2 | Scheduled/background roll-forward | App refresh now auto-materializes accepted previews at the boundary, but no server-scheduled job exists for athletes who do not open the app that day. | App-refresh automation covers normal use, but a server job may later improve durability for long gaps between sessions. | Decide whether to add a scheduled Supabase job after production audit/event policy is settled. | Non-blocking. |

| P2 | Food logging depth | Food logging remains quick manual macro/fiber/sodium entry with grouped Fuel history only. Barcode scanning, full meal planning, and a detailed food database remain intentionally deferred. | Command confidence can improve from logs, but athletes cannot yet inspect routed detailed meal history or use a food database. | Add routed manual Fuel history only after review permissions settle; keep barcode scanning and meal planning deferred. | Non-blocking. |
| P2 | Completion UX density | Workout detail is still dense on mobile. | The flow is functional but can feel heavy during post-workout logging. | Split completion into a lightweight sheet or stepper while preserving `prescribed_only` defaults. | Non-blocking. |

| P3 | Calendar polish | Plan has no drag/drop or calendar package. | Weekly command center is sectioned and readable but not yet a full planner. | Add after preview materialization, coach permissions, permissioned adjustment commands, and boxer user testing are hardened. | Non-blocking. |
