Do not treat the 2026-06-18 historical pass as proof for a future release candidate after additional migrations, function changes, or config changes. Generated evidence must record a fresh migration list and dry-run for the exact candidate SHA.

## Remote Mutation Guard

Applying remote migrations is release-owner work. Before mutating the remote database:

- Confirm release-owner credentials and permissions are available.
- Require explicit local opt-in: `CORNERIQ_ALLOW_REMOTE_DB_PUSH=1`.
- Do not print access tokens, DB passwords, service-role keys, smoke credentials, or personal emails.
- After any apply, rerun migration list and dry-run and record only non-secret results.

Without that guard, do not apply remote changes. If fresh exact-candidate evidence is unavailable, treat remote alignment as unverified for that release candidate.

## Live Smoke Status

The production account-deletion smoke passed on 2026-06-18 after remote migration alignment and the CORS-enabled `delete-account` v2 deployment. A fresh generated release evidence artifact should still record live-smoke status for each final candidate.

Required non-secret evidence when a release owner runs it:

- Date/time.
- Candidate SHA.
- Command: `cmd /c npm run smoke:live-db` with `CORNERIQ_LIVE_DB_SMOKE=1`.
- Public URL env present: yes/no.
- Public anon key env present: yes/no.
- Public env names: `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`.
- Smoke email/password env names present: yes/no, without values.
- Pass/fail.
- Rows created and cleaned summary.

The regular suite still includes `src/tests/live/liveDbSmoke.test.ts`; it skips unless `CORNERIQ_LIVE_DB_SMOKE=1` is set.

Account-deletion smoke evidence should additionally record the non-secret result of:

- Sign in with a confirmed production review/smoke account.
- Open Profile > Data > Danger Zone.
- Type `DELETE ACCOUNT` and confirm.
- Verify the app signs out.
- Verify the deleted credentials can no longer sign in.
